## 2024-05-23 - Math.pow and Inline Function Overhead in Tight Loops
**Learning:** In highly-executed paths like `deltaE2000` (which calculates color distance across potentially millions of pixel tests in `rescueShapes`), small wrapper functions (like `p7(v)`) and `Math.pow(v, 2)` calls accumulate noticeable performance overhead. Explicitly expanding integer exponentiation (`v*v`) and replacing inline functions with direct calculations improves execution speed significantly without destroying logic clarity.
**Action:** When working on math-heavy utility functions used in pixel-level tight loops, prefer explicit multiplication for small constant integer powers over `Math.pow()` and avoid allocating tiny utility closures per-call if they can be inlined or expanded manually.
